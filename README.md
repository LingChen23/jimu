# Intelligent Building Blocks

12 路 nRF52832 运动数据采集、BLE 网关、三路聚合和 PC 可视化系统。

## 目录结构

- `tx_device/`：nRF52832 传感器 Keil 工程。
- `ble_gateway/`：ESP32-S3 四连接 BLE 网关 ESP-IDF 工程，单工程生成 A/B/C 三套固件。
- `aggregator/`：ESP32-S3 三路双向 UART 聚合器 ESP-IDF 工程。
- `pc_visualizer/`：支持 12 台设备的接收、控制、可视化和运动分析程序。
- `nrf52832_12nodes_ble_gateway_aggregator方案.md`：12 台传感器、3 台 BLE 网关和1台聚合器的总体方案。

## 当前完成状态

原有四设备稳定版本已标记为 `v0.1.0-four-node-stable`。当前已经完成并验证三路十二设备硬件闭环；新的稳定回退基线为 `v0.2.1-12-node-stable`：

```text
nRF 1～4  ─BLE─> 网关 A ─UART─┐
nRF 5～8  ─BLE─> 网关 B ─UART─┼─> 三路聚合器 ─原生 USB / COM23─> PC
nRF 9～12 ─BLE─> 网关 C ─UART─┘
```

三路聚合器已经实现三路独立 UART、分路队列、公平合并、设备 1～12 命令路由、链路诊断和聚合器健康状态。只连接 A、只连接 B 或仅连接部分网关时，也可以独立运行。

当前 `fix/ble-ce-fairness` 分支在该回退基线上继续修复连接事件公平性：三台网关已更新，A 组改为31.25 ms，所有连接统一使用5 ms事件上限；设备1已升级为nRF固件0.2.2并完成零丢包验证，设备2～4待依次升级和最终12节点回归。

### 网关分组

| 网关 | nRF 设备 | 稳态连接间隔 | BLE 启动延迟 | 当前状态 |
| --- | --- | ---: | ---: | --- |
| A | 1～4 | 31.25 ms | 0 s | 网关及设备1已验证；设备2～4待升级 |
| B | 5～8 | 32.5 ms | 1.5 s | 地址已配置，已烧录并验证 |
| C | 9～12 | 35 ms | 3 s | 地址已配置、已烧录并完成十二设备闭环 |

三块共址网关统一采用 0 dBm，nRF52832 上行仍为 +4 dBm；现场测试确认单独提高网关 B 功率会把干扰扩散到 A/C，因而不采用。37个 BLE 数据通道按交错方式分为互不重叠的 A/B/C 三组，使每组都覆盖完整频段并避免同信道碰撞；现场测试表明，连续窄频段、统一 -12 dBm 或过短连接事件都会降低部分节点吞吐。断线重连使用低占空比被动扫描：扫描间隔100 ms、窗口10 ms、每次扫描1秒、暂停4秒后重试。连接阶段会请求 DLE；当前所有连接的单次连接事件上限统一为5 ms，避免单个弱信号节点长期占用无线时隙。

### nRF52832 固件

当前代码版本为 `0.2.2 / Motion V2`。设备1已升级到0.2.2；设备2～4待升级，设备5～12继续运行功能兼容的0.2.1：

- 100 字节运动数据包；
- 100 Hz 六轴采样，6组采样封装为1包，约16.67包/秒；
- 50 Hz 设备坐标；
- 加速度量程 ±8 g，角速度量程 ±1000 °/s；
- BLE 发射功率 +4 dBm；
- 32 包发送队列；
- 主循环有效看门狗；
- 电池电压和运行诊断；
- 每次启动和重新校准生成新的随机 `session_id`，避免复位前后数据拼接；
- `START_STREAM`、`STOP_STREAM`、`GET_INFO`、`GET_STATUS`、`RESET_STATS`、`RECALIBRATE`、`REBOOT` 命令。

每台设备约在连接5秒后主动请求本组连接间隔，保证重连后仍恢复为 A=31.25 ms、B=32.5 ms、C=35 ms。A组使用31.25 ms以避免与60 ms运动包节拍长期锁相。

三网关、聚合器与PC均使用V1/V2双协议兼容版本。当前12台均已完成V2升级，
兼容能力保留用于维护和滚动升级，不用于当前稳定基线的日常运行。

### 十二设备 Motion V2 稳定基线

12台设备已经完成版本、编号、网关分组和随机会话核验，并分别通过60秒静态
测试和60秒同时移动压力测试：

- 设备1～12全部为固件 `0.2.1`、协议2、数据源 `Motion V2/6样本`；
- 12个 `device_id` 完整且无重复，12个 `session_id` 互不重复；
- 网关A/B/C分别连接设备1～4、5～8、9～12，实际连接间隔为30/32.5/35 ms；
- 每台约16.6～16.8包/秒，仍向PC提供100 Hz六轴样本；
- 两轮测试中12台的nRF队列丢弃、传感器错误、网关序号间隙、PC丢包、乱序和断连全部为0；
- 三路UART、聚合器队列、USB、CRC、COBS和输入溢出新增错误全部为0；
- 移动测试瞬时RSSI最低约为 -106 dBm；部分设备出现SoftDevice资源等待，
  但32包队列成功吸收短时背压，测试结束队列深度为0且没有形成真实丢包。

历史V1在25包/秒下的压力复测曾出现设备1丢334包、设备7丢41包。提高网关
功率、改变信道组和延长单次连接事件没有稳定消除问题。Motion V2把12台总
空口通知率由约300包/秒降至约200包/秒，同时保持100 Hz特征计算输入，已在
上述静态和移动测试中验证解决持续带宽与调度瓶颈。

历史两路八设备稳态检查如下：

设备 1～8、网关 A/B、聚合器和 PC 已完成60秒稳态增量检查：

## 工程入口

### nRF52832

使用 Keil 打开：

```text
tx_device/tx.uvprojx
```

烧录不同设备前，在 `tx_device/include/tx_device_config.h` 中设置对应的 `TX_DEVICE_ID`，然后选择 `nrf52832_xxaa` 目标执行 `Rebuild` 和 `Download`。

### BLE 网关

在 ESP-IDF 5.2.3 环境中生成三套固件：

```powershell
cd ble_gateway
./build_gateway_profiles.ps1 -Profile All
```

构建目录分别为 `build-gateway-a/`、`build-gateway-b/` 和 `build-gateway-c/`。

### PC 可视化程序

```powershell
cd pc_visualizer
python app.py
```

业务串口为聚合器原生 USB 串口，当前使用921600波特率打开 COM23。
