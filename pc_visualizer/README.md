# PC Motion Visualizer（WebGL 真三维、短段过滤、分段历史）

这是 Motion V1 的本地 PC 可视化工具，支持 1～12 号设备，并行运行：

1. **设备状态驱动**：沿用 TX 的 `coordinate_flags` 分段；
2. **PC 独立判定（默认）**：设备状态仅作参考，PC 根据当前加速度和角速度独立判断移动开始和结束。

## WebGL 真三维轨迹

主轨迹和历史详情轨迹改为本地内置的 Plotly `scatter3d` WebGL 场景：

- 不再使用等轴测公式把三维点手工投影到二维 Canvas；
- 三维相机、坐标变换和投影由浏览器 GPU 完成；
- 默认使用正交相机，减少透视造成的尺度失真；
- 支持拖动旋转、滚轮缩放和平移；
- 支持三维、XY、XZ、YZ 视角预设；
- 米制模式使用三轴数据比例；
- Plotly 已放在 `static/vendor/plotly.min.js`，运行时不依赖互联网。

浏览器内部仍会创建 WebGL 渲染画布，但业务代码不再把三维坐标手工投影成二维折线。浏览器未启用 WebGL 时，会自动回退为 Plotly SVG 的 XY/XZ/YZ 正交视图，而不是显示空白或伪三维。

## 取消显示端指数平滑

轨迹不再执行自适应指数平滑，不修改顶点位置。仅在点数超过 4000 时进行固定步长抽点，以控制浏览器绘制负载；保留下来的点仍是原始轨迹点。

## 最短有效移动时长

“完整移动统计”标题栏增加：

```text
最短有效移动(s) [0.30] [应用]
```

默认值为 `0.30 s`，可设置为 `0～60 s`。移动结束后，如果有效移动时长小于阈值，该候选段将：

- 不进入历史记录；
- 不占用移动编号；
- 不参与速度统计、震颤 FFT 和会话平均；
- 不保留为当前轨迹；
- 计入“已忽略短段”。

设置对所有设备和 PC/设备两种分析模式生效，并保存到程序目录的 `motion_settings.json`。提高阈值时，当前会话中已经存在的短记录会立即移除并重新连续编号；降低阈值不会恢复此前已丢弃的短段。


## 5% 分位速度

原“最小速度”包含动作起点的零速度和零末速度约束，因此通常恒为 `0 m/s`。当前页面改为显示运动核心区间速度的 5% 分位数（P05）：

- 排除每段首尾各 10%，每侧最多 100 ms；
- 排除标记为静止的样本；
- 对剩余速度样本取第 5 百分位；
- 原始逐样本速度仍完整保存在 CSV/JSON 中。

该指标比绝对最小值更适合比较不同移动段的低速水平。

## 分段记录

每段有效移动结束后记录：

- 最大速度、5%分位速度、平均速度、中位速度和速度总体标准差；
- 方向一致、未完成角度遇到反向会抵消的完整旋转次数；
- 基于设备上下方向反转的翻转次数；
- 震颤主频、震颤强度和震颤频带 RMS；
- 会话平均震颤频率和强度；
- 移动中稳定静止至少 0.8 秒、随后恢复移动的停顿次数和时长；
- 掉落次数和冲击强度；
- 三轴加速度、角速度、速度、PC 轨迹和设备轨迹；
- 北京时间和电脑本地开始/结束时间；
- CSV/JSON 单段导出。

停顿不再使用低重力/自由落体定义。设备被手拿着悬空不动，只要稳定静止
至少 0.8 秒并在本段结束前恢复移动，也会计为一次停顿。末尾静止属于移动
结束，不计为停顿。

## 页面指标计算说明

本节对应当前 Web 页面显示的全部主要指标。页面同时包含三类数据：

- **nRF 直接上报**：设备信息、电池电压、运行状态、异常计数和设备坐标；
- **ESP32/链路统计**：USB 帧数、网关丢帧、CRC 错误和每设备数据包丢失；
- **PC 计算**：移动分段、姿态、速度、轨迹、旋转、翻转、停顿、晃动、掉落和震颤。

除设备上报的坐标外，页面中的 PC 速度和位置都是六轴 IMU 惯导估算值，
适合比较动作和轨迹形状，不是经过外部定位系统标定的真实距离或速度。

### 1. 原始数据换算和时间

| 项目 | 计算方法 |
| --- | --- |
| 加速度 | nRF 发送 ICM-20689 的三轴 `int16` 数据，量程为 `±8 g`、灵敏度为 `4096 LSB/g`。PC 先计算 `raw × 9.80665 / 4096`，再应用当前三轴标定偏移和矩阵，单位为 `m/s²`。实时加速度曲线是包含重力的比力。 |
| 角速度 | nRF 发送三轴 `int16` 数据，量程为 `±1000 °/s`、灵敏度为 `32.8 LSB/(°/s)`。PC 计算 `raw / 32.8`，单位为 `°/s`。姿态、旋转和震颤使用扣除 PC 估计零偏后的角速度。 |
| 样本间隔 | `dt = (current_tick_32k - previous_tick_32k) / 32768`。所有持续时间和积分优先使用设备 RTC，而不是 USB 到达时间。 |
| 电脑/北京时间 | 每帧到达 PC 时建立 RTC 与电脑时间的锚点，再按样本 RTC 回推每个样本的时间；北京时间固定使用 UTC+8。 |

### 2. 串口和设备状态区

| 页面指标 | 含义和计算方法 |
| --- | --- |
| `COM / 波特率 / 帧` | 当前打开的端口、配置值和 PC 成功解码的 ESP32 网关业务帧数。原生 USB CDC 不使用实际 UART 波特率，页面仍保留该配置值用于接口统一。 |
| `GW丢` | 根据 ESP32 网关帧中的 32 位 `gateway_sequence` 检查相邻序号间隙并累加。它表示 ESP32→PC 链路缺帧。 |
| `CRC错` | COBS 解码成功后，CRC-32/IEEE 校验不通过的网关帧数量。 |
| 在线/离线 | 对应设备最后一个有效数据包距当前时间小于 3 秒时显示在线。 |
| 解析数据包 | 当前设备通过协议校验并交给分析器的 Motion V1 数据包累计数量。 |
| 数据包丢包 | 根据当前设备 16 位 `packet_sequence` 的相邻序号间隙累加。它表示 nRF→ESP32→PC 完整链路中该设备缺少的数据包数。 |
| 最新样本序号 | 最近收到的 100 Hz IMU 样本序号。每个 100 字节数据包包含 4 个连续样本。 |
| 数据源 | `完整 100B` 表示 COBS+CRC 网关帧中的完整 Motion V1 包；`诊断 S0` 表示兼容的稀疏文本诊断数据。正式测试应使用完整 100B。 |

### 3. SmartBlock 设备控制区

该区域的数据不是 PC 估算，而是点击 `设备信息` 或 `运行状态` 后由 nRF
通过 BLE 控制响应返回。命令路径为 PC → ESP32-S3 USB → BLE → nRF52832。

| 页面指标 | 来源和含义 |
| --- | --- |
| 电池电压 | nRF SAADC 测量原理图 `BAT_ADC`（电池分压）后换算得到的 `battery_mV`。显示的是电池当前端电压，不是“3.7 V”标称值；`≤3400 mV` 时同时显示低电压。 |
| 数据流 / 校准 | `streaming` 表示 nRF 是否允许发送 Motion V1 通知；`calibrated` 表示设备端轨迹算法是否已完成静止校准。 |
| 传感器 / 运行时间 | `sensor_ok` 来自 nRF 的 IMU 工作状态；运行时间按本会话累计有效采样数除以 100 Hz 得到。 |
| 固件 / 量程 | `GET_INFO` 返回的固件版本、加速度量程和角速度量程。当前目标为 `±8 g / ±1000 °/s`。 |
| 采样 / 坐标频率 | nRF 声明的 IMU 采样率和坐标输出率，当前为 `100 Hz / 25 Hz`。 |
| 异常计数：间隙 | nRF 发现数据就绪时间戳或采样节拍不连续的累计次数。 |
| 异常计数：传感器 | IMU 读取或传感器处理失败的累计次数。 |
| 异常计数：队列 | 32 包发送队列满时覆盖/丢弃旧包的累计次数。 |
| 异常计数：BLE | BLE SoftDevice 暂时没有发送资源、需要稍后重试的累计次数。它不一定等于丢包。 |
| 复位原因 | nRF 启动时读取的硬件复位原因位，例如看门狗、软件复位或掉电复位。 |
| 会话 | `session_id`，用于区分两次上电或重启；同一设备会话变化后不应把前后轨迹拼接。 |
| 当前队列 | 查询瞬间 nRF 32 包发送队列中尚未成功发送的包数。 |
| ESP连接 / 实际连接间隔 | ESP32 为固定设备地址保存的连接状态，以及 NimBLE 当前连接描述中的实际间隔；协议原始单位为 1.25 ms。 |
| 实际 ATT MTU / DLE 请求 | 当前连接实际协商的 ATT MTU，以及 ESP32 逐连接请求 251 字节 DLE 的同步返回结果。 |
| DLE TX / RX | NimBLE 的 DLE 完成事件给出的实际收发链路层负载字节数与时间；用来确认连接是否仍停留在默认 27 字节。 |
| PHY TX / RX | ESP32 读取的当前发送和接收 PHY，例如 `1M / 1M`。 |
| RSSI / 接收速率 | ESP32 每秒读取一次当前连接 RSSI；接收速率分别为最近约 1 秒和滚动 10 秒内收到的有效 Motion 包速率，正常目标约为 25 包/s。 |
| ESP累计接收 / 序号缺口 | ESP32 从本次启动开始累计的有效 Motion 包，以及同一连接内根据 16 位包序号发现的缺失包数量。 |
| 连接 / 断连 / 参数更新 | 对应固定设备地址的累计成功连接、断连和成功连接参数更新次数，临时 peer 释放后仍保留。 |
| 无效包 / 最后断连原因 | 长度、协议头或 `device_id` 校验失败的 BLE 通知数量，以及最近一次 NimBLE/HCI 断连原因码。 |
| 链路层真实重传 | ESP-IDF 5.2.3 的公开 NimBLE API 不提供控制器真实重传次数，页面明确显示不可直接读取，不使用序号缺口冒充重传。 |
| ESP发送队列丢弃 / 诊断龄 | ESP32 送往原生 USB 的 128 帧队列满时的累计丢弃数，以及该设备最近一帧链路诊断距当前页面查询的时间。 |

`清零设备计数` 清除 nRF 端异常统计；`清零轨迹与统计` 只清除 PC 当前设备
的轨迹和分析历史，两者作用域不同。

### 4. 移动分段和状态

页面并行运行两套分段，切换模式不会丢失另一套结果：

#### PC 独立判定（默认）

1. 启动后需要 100 个连续稳定样本，约 1 秒。稳定条件为
   `|加速度模长 - g| < 0.60 m/s²` 且 `角速度模长 < 5.73 °/s`。
2. 静止状态下，以下任一条件连续出现 2 个样本即开始移动：
   - 加速度相对静止基线变化 `≥0.45 m/s²`；
   - `|加速度模长 - g| ≥0.65 m/s²`；
   - 角速度模长 `≥8 °/s`。
3. 移动状态下，`|加速度模长 - g| <0.80 m/s²` 且角速度模长 `<6 °/s`
   连续 20 个样本（约 0.2 秒），确认进入静止；停止时间回溯到第一个安静样本。
4. 确认静止后继续等待：0.8 秒后页面显示“停顿中”；若恢复移动，记录一次
   停顿；若持续到 3 秒，则结束本段移动，末尾静止不记为停顿。

#### 设备状态驱动

移动开始和停止使用 nRF 上报的 `coordinate_flags` 中 `MOVING` 和
`STATIONARY` 状态；速度、姿态和事件仍由 PC 使用同一批 IMU 样本计算。

#### 状态和时间类指标

| 页面指标 | 计算方法 |
| --- | --- |
| 状态 | 当前分析管线状态：校准、静止、移动中、停止确认或停顿中。 |
| 设备参考 | nRF `coordinate_flags` 的状态文字，只作参考，不会覆盖 PC 独立判定结果。 |
| 移动时间 | 当前段中实际保存的非静止 IMU 样本 `dt` 之和。移动结束时会删除停止时间点之后的样本。 |
| 最短有效移动 | 移动时间小于该用户设置的候选段不进入历史、不编号、不参与 FFT 和会话平均。 |
| 已忽略短段 | 因移动时间小于“最短有效移动”而丢弃的候选段数量。 |

### 5. 速度、加速度和 PC 轨迹

PC 先使用四元数把设备坐标系加速度旋转到世界坐标系，再减去
`[0, 0, 9.80665] m/s²` 得到动态加速度。动态加速度模长小于
`0.06 m/s²` 时使用软死区抑制噪声。随后按样本积分：

```text
p(k+1) = p(k) + v(k)·dt + 0.5·a(k)·dt²
v(k+1) = v(k) + a(k)·dt
speed  = sqrt(vx² + vy² + vz²)
```

每次移动从 `p=[0,0,0]、v=[0,0,0]` 开始。静止时使用零速更新
（ZUPT），将速度归零。移动完整结束后再计算整段残余速度：

```text
acceleration_bias = final_residual_velocity / movement_time
corrected_acceleration = acceleration - acceleration_bias
```

然后从零速度重新积分，使“静止到静止”的段末速度回到零。页面最终历史速度
和 PC 轨迹使用该段后校正结果。

| 页面指标 | 计算方法 |
| --- | --- |
| 最大速度 | 本段所有最终校正速度模长的最大值。 |
| 5%分位速度 | 排除首尾各 10%（每侧最多 0.1 秒）以及静止样本后，对剩余速度模长取第 5 百分位。 |
| 平均速度 | 本段全部速度模长的算术平均。 |
| 中位速度 | 本段全部速度模长的中位数。 |
| 速度标准差 | 本段全部速度模长的总体标准差，分母为样本数 `N`。 |
| 加速度均值/最大/最小 | 历史详情分别统计校准后比力和世界坐标动态加速度的 X/Y/Z 与模长；均值为算术平均，标准差为总体标准差。 |
| 惯导速度（参考） | 实时速度向量的模长 `sqrt(vx²+vy²+vz²)`。 |
| PC 惯导位置 | 上述动态加速度双积分结果，单位为米，但会受零偏和姿态误差快速漂移。 |

### 6. 旋转、翻转、停顿、晃动和掉落

| 指标 | 判定方法 |
| --- | --- |
| 完整旋转 | 使用校正后三轴角速度的合成方向积分。角速度模长达到 `10 °/s` 开始，保持期间允许降到 `5 °/s`；当前方向与跟踪旋转轴的点积需 `≥0.65`。未完成角度遇到明显反向会抵消；方向中断达到 0.35 秒则清空未完成进度。累计有效角度达到 `330°` 计 1 次，为物理 360° 旋转保留起止低速采样损失余量。 |
| 翻转 | 以移动开始时设备本体 Z 轴在世界坐标系中的方向为参考；新方向与参考相差至少 150° 并持续 0.10 秒，计 1 次并把新方向设为下一次参考。翻回去会再计一次，绕本体 Z 轴的纯 Yaw 旋转不会计为翻转。 |
| 停顿 | 一次移动内部确认静止后持续至少 0.8 秒，并在 3 秒的移动结束确认之前恢复移动，计 1 次；持续时间为第一个静止样本到恢复移动样本的 RTC 时间差。手持悬空稳定不动仍接近 1 g，因此可以触发；低重力不是停顿条件。 |
| 剧烈晃动 | 世界坐标动态加速度模长 `≥1.5 g`，或校正角速度模长 `≥300 °/s` 时触发。必须先回落到动态加速度 `<0.7 g` 且角速度 `<150 °/s` 才解除，同一次触发至少间隔 0.45 秒，避免一个连续晃动被逐样本重复计数。该值显示在移动详情中。 |
| 掉落 | 比力模长 `≤0.35 g` 持续至少 0.08 秒后进入待冲击状态；随后 0.80 秒内检测到比力模长 `≥2.5 g`，计 1 次并记录冲击 g 值和时间。只有低重力而没有后续冲击不计掉落。 |

### 7. 震颤指标

震颤只在一段移动结束后计算，至少需要 64 个有效样本且移动数据跨度不少于
0.75 秒：

1. 使用扣除角速度零偏后的 X/Y/Z 三轴数据；
2. 按 RTC 时间重采样到等间隔序列；
3. 每轴进行 2 Hz 一阶高通并去均值；
4. 使用 Hann 窗和 4 倍零填充 FFT；
5. 在 3～20 Hz（且不超过采样率的 45%）内搜索三轴频谱矢量合成峰值。

| 页面指标 | 计算方法 |
| --- | --- |
| 本段震颤主频 | 3～20 Hz 分析频带中合成幅值最大的频率。 |
| 本段震颤强度 | 主频位置的三轴角速度频谱幅值合成，单位 `°/s`。 |
| 震颤频带 RMS | 对未加窗频谱仅保留 3～20 Hz 后逆变换，计算三轴带限信号合成均方根。 |
| 会话平均震颤频率 | 当前设备、当前分析模式中所有 FFT 有效的已完成移动主频的算术平均。 |
| 会话平均震颤强度 | 同一批有效移动的主频峰值幅值算术平均。 |

### 8. 姿态和轨迹显示

| 页面指标 | 计算方法和限制 |
| --- | --- |
| 四元数 `w,x,y,z` | PC 用角速度积分更新四元数；静止时利用重力方向校正 Roll/Pitch 并缓慢更新陀螺仪和加速度零偏。 |
| Roll / Pitch / Yaw | 由归一化四元数转换为内禀 XYZ 欧拉角。系统没有磁力计，Yaw 只相对本次初始方向，会随时间漂移。 |
| 设备轨迹 | nRF 发送的 `x_mm/y_mm/z_mm` 除以 1000，并减去本段第一个有效坐标，使每段从 `[0,0,0]` 开始。 |
| PC 轨迹 | PC 世界坐标动态加速度双积分；完整段使用静止到静止残余速度校正。 |
| 相对形状 | 设备轨迹与 PC 轨迹分别执行 `p'=(p-p0)/scale`，其中 `scale=max(三轴最大跨度, 距原点最大半径, 1e-6)`。两条轨迹分别归一化，只比较方向和形状，不能比较真实尺度。 |
| 米制估算 | 设备坐标按协议毫米换算为米；PC 坐标显示双积分估算米值。两者都不进行显示端指数平滑。 |
| 三维 / XY / XZ / YZ | 仅改变 Plotly 相机或正交投影视角，不修改轨迹数据。 |

实时加速度和角速度曲线最多保存最近 1000 个样本；普通实时绘图显示最近
400 个点。轨迹数据超过显示上限时采用固定步长抽点，并保留终点；抽点不做
插值，也不会改变被保留点的数值。历史详情和 CSV/JSON 导出保留本段统计、
事件、时间、设备坐标以及逐样本 PC 计算数据。
