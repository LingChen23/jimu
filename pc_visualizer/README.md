# PC Motion Visualizer（WebGL 真三维、短段过滤、分段历史）

这是 Motion V1 的本地 PC 可视化工具，支持 1～12 号设备，并行运行：

1. **设备状态驱动**：沿用 TX 的 `coordinate_flags` 分段；
2. **PC 独立判定（默认）**：设备状态仅作参考，PC 根据当前加速度和角速度独立判断移动开始和结束。

## WebGL 真三维轨迹

主轨迹和历史详情轨迹改为本地内置的 Plotly `scatter3d` WebGL 场景：

- 不再使用等轴测公式把三维点手工投影到二维 Canvas；
- 三维相机、坐标变换和投影由浏览器 GPU 完成；
- 默认使用正交相机，减少透视造成的尺度失真；
- 支持拖动旋转、滚轮缩放和平移；
- 支持三维、XY、XZ、YZ 视角预设；
- 米制模式使用三轴数据比例；
- Plotly 已放在 `static/vendor/plotly.min.js`，运行时不依赖互联网。

浏览器内部仍会创建 WebGL 渲染画布，但业务代码不再把三维坐标手工投影成二维折线。浏览器未启用 WebGL 时，会自动回退为 Plotly SVG 的 XY/XZ/YZ 正交视图，而不是显示空白或伪三维。

## 取消显示端指数平滑

轨迹不再执行自适应指数平滑，不修改顶点位置。仅在点数超过 4000 时进行固定步长抽点，以控制浏览器绘制负载；保留下来的点仍是原始轨迹点。

## 最短有效移动时长

“完整移动统计”标题栏增加：

```text
最短有效移动(s) [0.30] [应用]
```

默认值为 `0.30 s`，可设置为 `0～60 s`。移动结束后，如果有效移动时长小于阈值，该候选段将：

- 不进入历史记录；
- 不占用移动编号；
- 不参与速度统计、震颤 FFT 和会话平均；
- 不保留为当前轨迹；
- 计入“已忽略短段”。

设置对所有设备和 PC/设备两种分析模式生效，并保存到程序目录的 `motion_settings.json`。提高阈值时，当前会话中已经存在的短记录会立即移除并重新连续编号；降低阈值不会恢复此前已丢弃的短段。


## 5% 分位速度

原“最小速度”包含动作起点的零速度和零末速度约束，因此通常恒为 `0 m/s`。当前页面改为显示运动核心区间速度的 5% 分位数（P05）：

- 排除每段首尾各 10%，每侧最多 100 ms；
- 排除标记为静止的样本；
- 对剩余速度样本取第 5 百分位；
- 原始逐样本速度仍完整保存在 CSV/JSON 中。

该指标比绝对最小值更适合比较不同移动段的低速水平。

## 分段记录

每段有效移动结束后记录：

- 最大速度、5%分位速度、平均速度、中位速度和速度总体标准差；
- 完整旋转次数和累计圈数；
- 震颤主频、震颤强度和震颤频带 RMS；
- 会话平均震颤频率和强度；
- 空中停顿次数（不再统计或导出滞留时长）；
- 掉落次数和冲击强度；
- 三轴加速度、角速度、速度、PC 轨迹和设备轨迹；
- 北京时间和电脑本地开始/结束时间；
- CSV/JSON 单段导出。

不再计算翻转，仅保留旋转累计。

## 启动

```powershell
cd pc_visualizer_p05_no_airborne_time
python -m pip install -r requirements.txt
python app.py
```

打开：

```text
http://127.0.0.1:8765
```

## 设置 API

读取：

```http
GET /api/settings
```

修改：

```http
POST /api/settings
Content-Type: application/json

{"minimum_movement_seconds":0.50}
```

## 测试

```powershell
python -m unittest discover -s tests -v
```

当前测试覆盖协议、双模式分段、短段过滤、连续编号、旋转累计、运动核心区间 P05 速度、6 Hz FFT、空中停顿计数、掉落、历史详情和导出。
